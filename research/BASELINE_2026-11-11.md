# Baseline 1: what the first real tablet numbers say  (TASKS P2, first pass)

Source: the **Copy report** text of Optimizer v0.2.0, pasted by the owner on 2026-11-11 about 22:50Z (`research/tablet/2026-11-11-app-report-v0.2.0.txt`). It is the first time the app ran on the tablet: it installed over v0.1.0 and ran without crashing.
Taken once, on a tablet that had been up 6 days; the owner did not say what was open at the time. `[?]` = needs the PC survey (`tools/adb/README.md`) to settle. Nothing here proves a cause of sluggishness; it says where to look first.

| Fact | Value | What it means |
| :- | :- | :- |
| **Storage (data)** | **996 MB free of 27.75 GB (3%)** | **The standout number.** A 32 GB-class tablet that is 97% full. Android's own low-storage alarm is near 500 MB `[?]`, so it is not yet firing, but there is no room for updates, caches or temporary files; flash that is nearly full is also known to slow down writes `[U]`. This is very likely why the Browser's updates needed so much space (Browser `UPDATE_STORAGE.md` assumed a 16 GB tablet; this partition is 27.75 GB). **Freeing space is now lever number 1.** |
| Storage speed | sequential write + fsync 31.3 MB/s; 4 KB synced write mean 1.74 ms, 95th percentile 5.93 ms (about 576/s) | The flash itself is NOT slow right now: both numbers are normal for eMMC. So 3% free is not (yet) the measured cause of lag; re-run the test after freeing space and compare. |
| Swap | **621 MB used of 1.72 GB** | The swap area is very large (90% of RAM) and a third full. `[?]` whether it is zram (compressed RAM: cheap, effective RAM grows, but every swapped page costs CPU) or a file/partition on the flash (every swap-in is a storage read: that would be slow and would also wear the flash). The app cannot tell: Android 10 hides `/proc/swaps` from apps. |
| RAM | 1.91 GB total, 691 MB available (35%), 131 MB free, 630 MB file cache; memory not low (threshold 144 MB) | Healthy at that moment. "Free" is small on purpose: the kernel uses spare RAM as file cache (that is good, not a leak). |
| Uptime | 6 days 2 h 40 min | Long for a 2 GB Go tablet: fragmentation and swapped-out pages build up. A restart before/after benchmark would show how much this matters `[?]`. |
| Heat | NONE (cool) | No throttling at that moment. |
| CPU | 4 x Cortex-A53, crypto extensions present (`aes pmull sha1 sha2 crc32`) | Answers the Browser research's open question: TLS and hashing have hardware help. |
| Heap | 128 MB per app (256 MB large) | As documented. |
| This app | 28 MB PSS while open | The baseline cost of any Activity on this ROM, mostly Android's own libraries. Optimizer runs nothing in the background, so this is only paid while the screen is open. |
| Animation scales | 0.0 / 0.0 / 0.0 | Consistent with the Launcher holding them at 0 during a stock-launcher session (the owner's rule: off only in Quickstep). Optimizer only reads them. |
| Memory-pressure counters, swap device | n/a | Android 10 does not let apps read `/proc/vmstat` or `/proc/swaps`. They need the PC survey, which reads them through adb. |

## What changes in the plan
1. **Storage first.** New top lever: find what fills the 27.75 GB and free it, safely and only with the owner's say-so on each item. Needs (a) a breakdown the owner can see on the tablet (planned v0.3.0 "What uses my storage": per-app size, data and cache, plus images/video/audio/apps totals, read-only, opens each app's Android storage page; it never deletes anything), and (b) the PC survey, extended with `dumpsys diskstats` and folder sizes.
   Likely suspects, to be confirmed with numbers, not assumed: old APK installers in Downloads (each Browser alpha is about 92 MB), the Browser's disk cache and downloads, photos/videos, app data and caches.
2. **Identify the swap** (zram or flash) and read the thrash counters: PC survey.
3. **Restart as a measured experiment**: benchmark right after a restart vs at day 6 (TASKS P3). Not a feature: the owner can restart any time.
4. The storage speed test becomes the before/after yardstick for the clean-up.
5. Tell the Browser sessions (through the owner): the update storage rule in `UPDATE_STORAGE.md` was derived for a 16 GB tablet; this one is 27.75 GB with 3% free.
